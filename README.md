# Readme

This project provides a parent POM file that can be used as starting point for using [JEAF Generator](https://www.jeaf-generator.io). Besides the Maven plugin configuration for JEAF Generator itself the POM also provides:

* Properties for **all** configuration parameters supported by JEAF Generator (see below) together with reasonable default values.
* Ready to use **profiles** to run code generation either from a local XMI file or from a Maven artifact, to bootstrap / update a Maven project structure and to perform an OSS release.
* **Dependency management** for all Maven artifacts that are typically required together with JEAF Generator (JEAF REST API, JEAF Validation API, Spring Boot, Jackson 2 / 3, JUnit).
* Default configuration for compiler, jar, build-helper, deploy, versions and surefire plugins.

<br>

## How to use this POM

Basically you have two options:

* use this POM as parent POM for your projects
* copy it and use it as a template for you own POM

<br>

## How does this POM work

### JEAF Generator Configuration

This POM defines properties for all configuration parameters that are supported by JEAF Generator together with their default values. The actual Maven plugin configuration (`pluginManagement` for `jeaf-generator-maven-plugin`) simply references these properties. This means that in your own POM you never have to touch the plugin configuration itself &mdash; you only have to override the properties that you want to change.

Whenever new configuration parameters will be introduced by JEAF Generator then this parent POM will be updated and a new version will be released.

<br>

This POM also provides dependency management (`<dependencyManagement>`) for artifacts that are commonly needed together with code that is generated by JEAF Generator:

### Profiles
In addition to all configuration parameters this POM also defines profiles to simplify usage of JEAF Generator:

* **`RunCodeGenerationFromXMIFile`**<br>Runs the code generation process using an XMI file that is stored on the local file system. XMI files are a tool independent representation of your UML model (e.g. exported from [MagicDraw UML](https://www.3ds.com/products/catia/no-magic/magicdraw)).<br><br>

* **`RunCodeGenerationFromModelArtifact`**<br>Runs the code generation process using a Maven artifact that contains the XMI files of the UML model.<br><br>

* **`UseDefaultProjectTemplate`**<br>Automatically activated profile (whenever property `jeaf.xmiDirectory` is **not** set) that configures JEAF Generator to use the bundled default project template model (`Maven_Project_Template.uml`) when no explicit model is provided.<br><br>

* **`CreateMavenProject`**<br>Generates a complete Maven project structure that uses JEAF Generator for code generation. Using this profile is similar to using a Maven archetype to generate a project structure.<br><br>

* **`UpdateMavenProjectStructureFromXMIFile` / `UpdateMavenProjectStructureFromModelArtifact`**<br>Updates an already existing Maven project structure based on the definitions inside the UML model, either from a local XMI file or from a Maven artifact.<br><br>

* **`CheckinGeneratedCode`**<br>Configures `maven-scm-plugin` to automatically check-in generated sources (directory `src-gen`) as part of the build, e.g. to keep generated code under version control.<br><br>

* **`JEAFRelease`**<br>Bundles all plugins that are required for an OSS release to Maven Central (GPG signing, javadoc / sources jars, `central-publishing-maven-plugin`, `maven-release-plugin`).<br>

Besides the location from which the XMI files are read, profiles `RunCodeGenerationFromXMIFile` / `RunCodeGenerationFromModelArtifact` and `UpdateMavenProjectStructureFromXMIFile` / `UpdateMavenProjectStructureFromModelArtifact` do not have any further differences from each other.

<br>

## Usage as parent POM

Before you can start with code generation you have to provide a minimum set of information:

* Location of the XMI files (either on file system or as Maven artifact)
* Name of the main model file
* UML package



### Run Code Generation from local XMI file

To run JEAF Generator using a local XMI file you have to configure at least the following properties in your POM.

```xml
<properties>
	<!--
		Directory which contains all XMI files. The files have to be exported from
		MagicDraw UML using its Eclipse UML2 Export v2.x
		(File - Export To - Eclipse UML2 (v2.0x) XMI File)
	-->
	<xmiDirectory></xmiDirectory>

	<!-- 
		UML package (plus subpackages) which will be the one that is considered
		during code generation.
	--> 
	<umlPackage>com.anaptecs.jeaf.timetable.api</umlPackage>

	<!--
		Name of the model file that should be used. Usually it has the same name
		as the MagicDraw UML project. Only the name of the file has to be provided
		as we assume that the file is located in the XMI directory.
	-->
	<umlModelFile></umlModelFile>
</properties>
```



### Run Code Generation from Maven Artifact

To run JEAF Generator using a Maven artifact that contains the XMI files of the model, have to configure at least the following properties in your POM.

<br>

**Notes:**

* Please be aware when using the Maven Artifact approach that then your project also needs to have a Maven dependency on the artifact.
* In general we recommend to use the model artifact approach, as storing XMI files inside SCM systems like git will blow up repository sizes over time

<br>

```xml
<properties>
	<!--
		Group ID of the artifact that contains the XMI files of the UML model.
		
		The UML model can either be defined by pointing to the directory where the
		XMI files are located directly or by referencing an artifact that contains
		the XMI files.
	-->
	<modelArtifactGroupID></modelArtifactGroupID>

	<!--
		Artifact ID of the artifact that contains the XMI files of the UML model.
		
		The UML model can either be defined by pointing to the directory where the
		XMI files are located directly or by referencing an artifact that contains
		the XMI files.
	-->
	<modelArtifactArtifactID></modelArtifactArtifactID>

	<!--
		XMI Path inside the artifact that contains the XMI files of the UML model.
	-->
	<modelArtifactXMIPath>xmi</modelArtifactXMIPath>

	<!-- 
		UML package (plus subpackages) which will be the one that is considered 
		during code generation.
	--> 
	<umlPackage>com.anaptecs.jeaf.timetable.api</umlPackage>

	<!--
		Name of the model file that should be used. Usually it has the same name
		as the MagicDraw UML project. Only the name of the file has to be provided
		as we assume that the file is located in the XMI directory.
	-->
	<umlModelFile></umlModelFile>
</properties>
```

## Profiles

This POM defines the following profiles:
* **`RunCodeGenerationFromXMIFile`**<br>Profile can be used to generate code using a XMI files (UML model export) that is stored on the local file system.<br><br>
* **`RunCodeGenerationFromModelArtifact`**<br>Profile can be used to generate code using a Maven artifact that contains the XMI files of the UML model export.<br><br>
* **`UseDefaultProjectTemplate`**<br>Automatically activated profile that falls back to the bundled project template model if no XMI directory is configured.<br><br>
* **`CreateMavenProject`**<br>Profile can be used to generate a Maven project structure that uses JEAF Generator for code generation. Using this profile is similar to using a Maven archetype to generate a project structure.<br><br>
* **`UpdateMavenProjectStructureFromXMIFile` / `UpdateMavenProjectStructureFromModelArtifact`**<br>Profiles can be used to update Maven project structure based on the definitions inside the UML model. Depending on the variant of the profile this will either be done using XMI files from the local file system or from the Maven artifact. Both are defined inside of the project POM.<br><br>
* **`CheckinGeneratedCode`**<br>Profile can be used to automatically check-in generated code (directory `src-gen`) during the build using `maven-scm-plugin`.<br><br>
* **`JEAFRelease`**<br>Profile bundles all plugins required to perform an OSS release to Maven Central (GPG signing, javadoc / sources jars, `central-publishing-maven-plugin`, `maven-release-plugin`).<br>

<br>
